## What I did
- **Owner's request:** a website that shows judges, with pictures and animation, what happens to a work at each step.
  It should take a judge's own example, and each step should replay. Plan: `docs/plans/T092-visualization-engine.md`.
- **Engine:**
  - `drishti/explain.py` runs one work through the same `assess_work()` as the batch and lays out each step:
    - the masked input, and what was hidden;
    - the description cut into coloured runs, using the readers' own patterns: place, size or count, construction,
      purchase, not-allowed word, hidden detail;
    - the facts the readers found;
    - every check's result, with the data its picture needs;
    - the score's arithmetic, replayed from `fusion/calibrated.py`.
  - Route: `POST /api/v1/explain`, behind sign-in. It is built like the pre-sanction route, plus status and dates.
- **Built-in examples:** `data/trial/explain_examples.py` writes `apps/web/public/explain/examples.json`. There are
  seven made-up works in Jaunpur, checked against the dashboard's 40,935 works:
  - ordinary
  - temple
  - says nothing
  - one costly light
  - completed before recommended
  - two checks agree (the only CRITICAL)
  - a real work typed in again
- **Web page:** `apps/web/src/app/explain/` is public, so the examples work signed out.
  - Six steps, each replayable; Play all (moves on when each step's animation has played); arrow keys.
  - Animations are CSS only (`explain.css`); reduced motion is respected.
  - Your own example: a form posts to the route. Signed out, it asks for the demo sign-in.
  - Linked from the login page and the app menu ("Step by step").
- **Privacy, found while building it:** the examples' real neighbour descriptions showed names in "<name> ke avas".
  - The masker learned the residence spellings (pushed to #92, commit 63589a2): 13,564 → 13,776 descriptions masked.
  - Then I re-checked all 847 strings of the examples file: nothing the masker would hide, no accusing word, every

## Decisions made (and why)
- **The page computes nothing.** Every number is in the trace, and the test ties the trace to the pipeline. A judge
  sees what the engines really did, not a demo imitation.
- **The built-in examples are a static file,** so judges need no sign-in and the hosted database gets no new public
  access. Your own example uses the live engine behind the same sign-in as the pre-sanction check.
- **The examples are made-up works, placed in the district with the most dated recommendations.** The other works
  shown are real (work id, amount, date, masked wording) and no MP is named.
- **Two examples were reworded to match what the engines read.** "Rampur" is a common word for the repeat check, so
  the ordinary road names "Bhagwatipur". "Says nothing checkable" uses R12's reading (few words, no number, no place),
  not only "no object".
- **A seventh example, "two checks agree", was added.** Without it no example shows the score combining two chances,
  or the rule that Critical needs two different checks.

## Problems, traps, surprises
- **Building a public page from real data found a privacy gap the tests had not.** Read every string of a public
  file by eye before it ships.
- **Two traps in Next 16's lint (react-hooks):**
  - a counter changed inside a `.map()` during render is rejected, so precompute indices in a plain function;
  - setState directly in an effect body is rejected; setState in a promise or timer callback is fine.
- **Tailwind 4's `-translate-x-1/2` uses the CSS `translate` property.** So it does not clash with animations of
  `transform`, and a dot can be centred and popped at once.
- **`pkill -f "next start"` killed my own shell** (its command line matched). Kill the server by its PID.
