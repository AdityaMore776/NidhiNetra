## Decisions made (and why)
- Public = read-only. Saving a cost form or filming a site visit still needs a staff account: opening writes to
  anonymous visitors would let anyone fill the database or the storage bucket.
- A stale or bad token on a read route falls back to PUBLIC instead of 401, so an old browser tab never locks a
  visitor out; it grants nothing beyond no token.

## Problems, traps, surprises
- Supabase Auth self-signup is still enabled (`/auth/v1/signup` answered "email_address_invalid", not
  "signup_disabled"). A self-made account has no `profiles` row, so it gets 403 on saving routes and the public
  view on read routes: harmless, but the owner should turn sign-ups off in Supabase → Authentication → Sign In /
  Providers ("Allow new users to sign up").
