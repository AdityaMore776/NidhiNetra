## What I did
- Found during T060: `data/load_db.py` ran `TRUNCATE ... works ...`, which Postgres refuses once `cost_forms` and
  `site_visits` reference `works` (migrations 013, 014), so the next full reload would fail at its first step.
- `apps/engine/drishti/reload.py` `replace_works()`: the works go into a temp table, then an upsert writes only
  new or changed works (every column from the load; a column the load does not carry is reset, as the old
  empty-and-refill did); a work gone from the source is deleted unless a saved form or site visit points at it.
  `load_db.py` uses it and no longer truncates `works`.
- Owner (20 Oct): the cost forms and site visits saved so far are test data: wipe them **once**, never on later
  reloads. Done as migration `016_wipe_test_forms_once.sql`: a migration runs once per database
  (`schema_migrations`), so later saves are never touched.

## How I checked it (commands run and what they printed)
- `pytest -q tests/test_reload.py tests/test_migrate.py` -> 8 passed (in-place update, saved input kept, failed
  reload changes nothing, 016 wipes once and never again); `ruff check drishti tests` -> All checks passed.
- Full reload twice on a fresh pgserver with the real `data/build` (scratchpad `t169_reload_twice.py`): first load
  209,993 works, 104 MB; a probe cost form + site visit + two probe works added; second load "0 new or changed",
  "1 gone from the source removed, 1 kept for their saved form or site visit", 104 MB; RESULT PASS.
- First version rewrote every work on each reload: database 104 -> 186 MB (dead row copies). The upsert now skips
  unchanged works.

## Numbers measured (only from saved script output)
- Reload of 209,993 works: 9-10 s locally; database 104 MB after one and after two loads.

## Decisions made (and why)
- A work that left the source but has a saved form or visit is kept, so nothing typed in or filmed is ever lost.
- The wipe is a migration, not a flag on `load_db.py`: a flag could be run again by mistake; a migration cannot.

## Problems, traps, surprises
- An upsert of every row doubles the table on disk until VACUUM: compare before writing.
- `ruff check data/load_db.py` reports an import-order warning that was already there on main (data/ is not linted
  in CI); left as is.
