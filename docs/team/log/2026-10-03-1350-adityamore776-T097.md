## Decisions made (and why)
- **One YAML file defines the form.** The web form, the checks and the spec all read it, so they cannot drift.
- **Two levels of check, neither a flag.** `fix` blocks Submit; `confirm` is "correct it or confirm it". A confirmed
  value stands.
- **Materials are confirmed by the person.** The matcher only suggests, and only confirmed materials are ever compared.
  A wrong suggestion therefore cannot become a flag.
- **No price numbers as judgments in the form.** The material `guard`s are typing-mistake guards, several times wider
  than any price. The agent judges against measured references only.
- **The flag threshold is measured, not chosen:** the 98th percentile of the same kind of work in the district. The MP
  check is a second condition; above the MP's amount but normal for the size is a note, not a flag.

## Problems, traps, surprises
- **eSAKSHI's street lights mix solar lamps with grid lights on new poles.** The middle 80% is tight (±5%), but the
  98th percentile is 3.9× the median. Without the form's specification fields, any threshold either misses mark-ups or
  flags normal works.
- **Place matters as much as size.** A state-wide band for roads would be wrong for both Ghazipur and Mahrajganj.
- **Government sites are blocked from the cloud environment,** so the official rates (T096) need a human or a network
  setting.
