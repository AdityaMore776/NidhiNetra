## What I did
The owner: "make the website usable on phones as well, and also make them faster to load if you
can while keeping all the functionality".
- **Measured first** (`scripts/dev/phone_audit.mjs`, new): every page in Chromium as a phone
  (390 px, touch) with Lighthouse's mobile throttling, the median of three loads; what overflows
  the screen, also inside the form's frame.
- **Phone layout:**
  - works lists (queue, all works, dashboard) are cards on a phone, naming the agents that asked
    (a chip's tooltip needs a mouse);
  - the form map's section table is a compact list with an icon per agent; estimate and labour
    rows are cards;
  - the work intelligence form itself: below 560 px each table row is a card, each cell labelled
    with its column (a small script in the form labels rows added later too);
  - the form's frame takes its full height below the wide layout, so a phone scrolls one page;
    "Show in form" still scrolls to the field;
  - the 13 example filings are a dropdown on a phone;
  - a one-line top bar (search as an icon) and banner; section headers that wrap instead of
    squeezing their text; the queue's figures two a row.
- **Faster, same features:**
  - the sign-in code loads only with a sign-in cookie, or on signing in (`lib/supabase.ts`);
  - the Hindi font is not preloaded; one-word Hindi labels use the device's own font;
  - charts, the 3D scenes and the staff map load when near the screen (`WhenVisible`), the 3D
    once the page is idle; the landing page shows the emblem picture meanwhile;
  - smooth scrolling (Lenis, GSAP) only with a mouse; no prefetch of the sign-in page.

## Decisions made (and why)
- **Load later, never remove:** every feature is still there (3D, charts, smooth scrolling on a
  desktop, sign-in), each loaded when it is used.
- **The form's frame grows to its content below the wide layout** instead of scrolling inside the
  page: two scroll areas inside each other are hard on a phone.
- **No server rendering yet:** the app pages are drawn in the browser, so text still waits for the
  scripts. Moving the shell to the server is the next speed step, a larger change to the shared
  layout.

## Problems, traps, surprises
- **Turbopack refuses a `node_modules` symlink** pointing outside the project (a worktree of main
  could not build). Measured main by stashing the branch's changes instead.
- **`next/dynamic` needs its options as an object literal**, not built by a function.
- **Headless Chromium has no Devanagari font**, so the audit shows the Hindi web font on pages with
  a Hindi word; a phone uses its own.
- **`ss` shows no PID here**: stop a server by the PID from `ps`, never with `pkill -f`.
